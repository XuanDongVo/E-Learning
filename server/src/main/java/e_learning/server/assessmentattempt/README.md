# AssessmentAttempt backend scaffold

This package owns the official Assignment runtime and remains separate from ActivitySession.

## Present in this branch

- V43 schema for AssessmentAttempt, immutable question snapshots, one current answer per question, part results and lightweight events.
- JPA entities, repositories, request/response DTOs and snapshot contract.
- Sprint 1 DTOs: `AttemptIntroResponse`, `StartOrResumeAttemptRequest`, `AttemptRuntimeResponse`.
- Controller shells for:
  - `GET /v1/assignments/{assignmentId}/assessment-attempt/intro`
  - `POST /v1/assignments/{assignmentId}/assessment-attempt`
- Service method signatures: `getIntro(assignmentId, studentId)` and `startOrResume(assignmentId, studentId, request)`.

## Explicitly not implemented

Both service methods currently throw `UnsupportedOperationException`. The controller routes exist only so the FE request/response wiring can be reviewed; they are not functional API endpoints yet.

Business logic left for the project owner:
- Authenticate/authorize Student and validate Assignment target, published status, start/due policy and attempt state.
- Resolve the Student's ACTIVE class server-side and snapshot attribution.
- Enforce one official Attempt under concurrent first-start requests.
- Register/compare the stable credential without silent replacement.
- Build the immutable Composition/settings/internal grading snapshots and a separate safe student projection.
- Preserve server deadline on resume.
- Implement incremental answer persistence/revisions, timeout, grading, submit/result visibility and Assignment authoring lock in later slices.

## Session policy

Follow ADR 0027, `.agent/decisions/0027-single-active-tab-resumable-assessment-attempt.md`:
- one active same-browser tab via Web Locks with fail-fast conflict;
- stable UUID credential generated by the client and persisted before the first request;
- backend validates the credential on every mutation;
- no heartbeat, stale threshold, or automatic takeover in MVP;
- the generic runtime DTO never returns the credential.

## Do not infer verification

No backend compilation/tests, frontend lint/typecheck/build, Flyway validation or browser/E2E checks were run for this scaffold. The API is not ready for Student use until the owner completes the stubs and the current HEAD passes validation.
